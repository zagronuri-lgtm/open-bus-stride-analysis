## תפקיד בסוכן

Power BI הוא **נתוני אמת תפעוליים/רשמיים** להשוואה מול מדידת Open Bus Stride (אי-יציאה 2.1.1).

| מקור | מה מודד | שימוש |
|------|---------|--------|
| Power BI | אי-ביצוע רשמי (כולל רכיבים מעבר לאי-יציאה) + החרגות + נסיעות לחישוב | אמת / יעד כיול |
| Stride / `weekly_report` | אי-יציאה בלבד (חסם תחתון) | מדידה פתוחה, שחזור, אגרגציות |

**אל תחליף** את מדידת Stride במספרי BI בלי תיעוד פער. המטרה: לטייב התאמה, לא למחוק את ההבדל המתודולוגי.

## שדות KPI לשליפה מ־BI (עמוד נסיעות)

כשמשווים / מכיילים, רשום מהדוח:

1. `תאריך כספת אחרון` / latest safe date
2. `נסיעות` (סה״כ)
3. `נסיעות לחישוב` (מכנה אחרי החרגות)
4. `החרגות` (אם מוצג)
5. `אי ביצוע` (מונה)
6. אופציונלי: איחור, הקדמה, נסיעה אחרונה, תדירות נמוכה, לא מורשה
7. מסננים פעילים: Month / Branch / Cluster (ולאחר מכן סניף אם קיים)

**% רשמי BI** = `אי ביצוע / נסיעות לחישוב`  
**מקדם מכנה** = `נסיעות לחישוב / נסיעות`

## מסננים ידועים

## זרימת כיול מומלצת

1. פתח את קישור ה־BI; Reset; סנן Month (+ Branch/Cluster אם רלוונטי).
2. הרץ דוח שבועי, ואז חוברת כיול:
   ```bash
   python -m src.weekly_report --week-ending YYYY-MM-DD --output-dir outputs
   python -m src.powerbi_calibration \
     --weekly-xlsx outputs/דוח_שבועי_אי_ביצוע_YYYY-MM-DD.xlsx \
     --output-dir outputs
   ```
3. בחוברת `כיול_Stride_מול_PowerBI_*.xlsx`: הדבק KPI בגיליון «הדבק KPI מ-BI», והשלם עמודות BI בהשוואות.
4. השווה:
   - מכנה: נסיעות BI לחישוב מול מתוכנן Stride (אחרי החרגות לוח)
   - מונה: אי-ביצוע BI מול missing Stride (2.1.1)
   - פער % = רשמי − חסם תחתון (צפוי חיובי אם BI כולל איחורים/הקדמות חמורים)
5. תעד מגבלות: latency כספת, חוסר סנן יומי, הבדלי שמות סניף, ימים ב־`segment`/`drop`.
