## 3. API מול UI — מה קיים באמת
- **API v2 רשמי** (`~/.optibus/optibus_openapi.json`, 30 נתיבים, `/api/v2`, Bearer מ-`POST /token`): קריאת מפה, סט, datasetProps, timeplan, operational; **כתיבה רק לקטלוגי ריקים** (`/deadhead-catalogs/...`) ו-`POST /directions`. **אין** יצירת עותק, עדכון נסיעות, שינוי העדפות, הרצה או סטטוס משימה.
- **endpoints פנימיים של ה-SPA** (`/app/...`), עובדים רק עם `accessToken` גולמי מה-localStorage של דף Optibus (לא Bearer), כלומר מתוך דפדפן מחובר: `schedulesetFolderContent`, `datasetFolderContent`, `schedules/<id>/exportTrips`, `schedules/updateTrips` (POST multipart), `schedules/<id>` (PUT SAVE), `schedules/opHistory`, `schedules/stats/<savedId>`. לא תיעוד רשמי; עלול להשתנות; אין להשתמש בהם לעקיפת הרשאות (המסווג חסם יירוט/שימוש חוזר בטוקן ב-29.7).
- **UI בלבד, ללא חלופה שראיתי:** Save to New Dataset, בחירת קובץ להעלאה, Optimize settings, לחיצת OPTIMIZE, לוח המשימות (התקדמות/ביטול/timeout).
- **כלים בקוד שאינם מוכחים:** `optibus_mcp/tools_write.py` (update_trip_schedule/add_trip/update_depot/add_depot) קורא ל-`OptibusClient` שפונה ל-`/api/v1/schedules/<id>/trips/<tid>` (PATCH/POST) — נתיבים שאינם קיימים ב-OpenAPI v2, לא נבדקו, וההנחה היא שאינם עובדים. `apply_changes` ו-`ui_actions.py` מבוססי Playwright דרך `auth.get_browser_context` — ה-venv של שרת ה-MCP שבור (ENOENT) ולכן לא ניתנים להרצה כיום. **אין להסתמך עליהם.** MCP `tbgdom` (export_dataset) — לא מתחבר.
- **דפדפן:** החלונית המובנית של Claude Code (בשימוש הלילה) מספיקה לניווט, לחיצות, JS-inspection ו-fetch פנימי, אך **אין בה file_upload** ו-`navigate` נדחה כשהחלונית סגורה. Claude in Chrome (כרום של אורי) כולל `file_upload` על `<input type=file>` (מוכח 12.8, זיכרון `optibus-file-upload-works`) — זו הדרך לאוטומציה של ההעלאה; טרם נבדקה על `update-trips-from-file`.

## 6. תכנון המתאם המוצע (ללא מימוש עדיין)
מודול Python אחד בריפו (בעלות קלוד, נפרד מקוד התור של קודקס), עם צעדים אטומיים ומצב ניתן לשחזור:
1. `verify_source(schedule_id)` — API v2, חתימת נסיעות+העדפות+stats; שומר baseline חתום.
2. `await_copy(dataset_name)` — **שער-אדם**: מציג הוראה ("הקלד שם X ולחץ SAVE"), מזהה את הדאטהסט ב-`datasetProps`, את המפה ב-`schedulesetFolderContent`, ומאמת זהות מלאה למקור. (עם כלל הרצאה: מבצע לבד.)
3. `export_template(copy_id)` — EXPORT TRIPS בממשק (או fetch פנימי), sha.
4. `build_update_trips(template, package)` — עריכה-במקום לפי החבילה החתומה של קודקס: רק Arrival/Time לנסיעות ברשימה; דיף תא-מול-תא = ההבדלים היחידים; דוח.
5. `upload_update_trips(copy_id, file)` — Claude in Chrome `file_upload` (או שער-אדם) → readback: N שינויים בדיוק, 0 מחיקות → SAVE → savedId → readback.
6. `preflight_prefs(copy_id)` — בדיקת בלוקים מסוכנים (VBD, נעילות) והצגת שינוי מפורש להכרעה; החלה בפאנל; אימות דיף ב-API.
7. `launch(copy_id, mode)` — Optimize settings בממשק לפי המצב המאושר; OPTIMIZE; רישום זמן.
8. `wait(copy_id)` — דגימת API כל 3 דק׳ + קריאת לוח המשימות כל 30 דק׳; HOLD על תקיעה/timeout; ללא retry אוטומטי.
9. `readback_and_compare(copy_id, baseline, control?)` — SAVE, readback הגרסה השמורה, טבלת השוואה מקור/בקרה/ניסוי, ניתוח סטאק (סידורים לא משובצים → נסיעות/קווים), הוכחת מקור ללא שינוי.
כל צעד מחזיר JSON עם מזהים, sha, timestamps מהשעון, וסטטוס `done|held|blocked` — בהתאם לחוזה של קודקס (שדה חסר אינו אפס).

4. **Expert `<>` (YAML)** הוא נתיב כתיבה אמין להעדפות, אך **מדיניות אורי לסשן זה אוסרת YAML** — נשאר בפאנל (play-pause = `enabled:false`, אומת). ⚠️ הגדרות-ריצה נשמרות עם הגרסה; DISCARD מחזיר גם אותן; crew-relaxation ורדיו-AFB נכשלים בשקט ב-headless ⇒ config-diff ב-API לפני/אחרי כל שינוי (כבר במתכון).
5. **הקלסיפייר הוא מגביל-הישימות הגדול** (מאשר את §5.1): צעדי כתיבה דורשים כלל הרשאה מפורש מאורי או אדם בשער; אין עקיפה. **העלאת קבצים רק ב-Claude in Chrome** (`find "file input"` + `file_upload`; יש לפתוח קודם את התפריט, ה-ref מתחדש); בחלונית המובנית הזרקה >13KB נחסמה. Save to New Dataset ניתן להפעלה לפי ref, אך מומלץ להשאיר כאישור-אדם (סיכון מפת-מתכנן).
6. **חוזה הנסיעות** (כבר במתכון, מאושר): UPDATE TRIPS מוחק נסיעות חסרות; אינו משנה מסלול; `StopTimes.distance` = מרחק לקטע ⇒ אימות `distance` ב-API לפני SAVE = שער חובה.
7. **המלצה זולה:** שאלה פורמלית ל-Support Hub של Optibus ("schedule duplicate / updateTrips / optimize / task-status API?") — סוגרת את סעיף "יש/אין צורך מוכח ב-API" ברשימת הקבלה. עד תשובה: **אין API**. (טיוטה בלבד; שליחה לתמיכה דורשת את אורי.)
8. **מסלולים:** מסלול-1 "Claude + Chrome של אורי + אדם בשערים" (מדוד, ניתן למימוש עכשיו); מסלול-2 "API" רק אם Support Hub יאשר endpoint.

## 11. עדכונים מביקורת דנטה (התקבלה 30.9 10:3x) — צד הנתונים: חלקי
1. **מה מד־זמנים מייצא היום:** מסך 4 מפיק חוברת סקירה (החלטות/רציפות/השפעה) וכפתור נפרד "UPDATE TRIPS נקי" (buildLoadFile): 5 גיליונות, Trips ב-**19 עמודות** (ללא Existing/Custom/customer), קובץ **מלא** של כל נסיעות מפת היעד; משתנים רק Arrival ושורת היעד ב-StopTimes; Departure לעולם לא; נסיעה עם תחנות ביניים לעולם לא (blocked_intermediate; ב-34 התבניות 23,791 נסיעות כולן בשתי תחנות).
2. **הייצוא היום = "דוגמה — לא לטעינה":** eligibility דורשת תאריכי יעד וקוד יום מאומתים, ומסך 4 מעביר תמיד לא-מאומת; רמת A מורדת ל-R בכוונה (inferencePending), policy autoTiers=['A'] → **אפס שינויים אוטומטיים**. כלומר החבילה כיום = מפה מלאה ללא שינוי + מועמדים לבדיקה. תואם את החוזה (הפרדת מועמדים משינויים שעברו שער), אך פירושו שאין עדיין "שינויים כשירים" לזרימה אוטומטית.
3. **פער פורמט (חובה, קטן):** הקובץ שהתקבל ב-Optibus הלילה (ייצוא Optibus: 22 עמודות + גיליונות Stops/ReliefPoints/Taxis/Parameters, עם הסרת customer/Custom/tp) ≠ תבנית המנוע (19 עמודות, 5 גיליונות, ממשימת 027); `templateFromUpdateTrips` דוחה כותרות שונות. **הכרעה נדרשת: להצמיד את המנוע לפורמט שהתקבל בפועל (עריכה-במקום של ייצוא העותק) — ההמלצה שלי — ולאמת בהעלאת-קבלה אחת על עותק.**

5. **חסר לחבילת משימה (עבודת יום קצרה במנוע, לפי דנטה):** run_id וגרסת חוזה; hash קובץ המקור (trips_sha256 9966339d / da5524ba + freshness_manifest קיימים ב-meta, לא בפלט); דקות יום שירות מפורשות 24+ (departure_min/arrival_min); סכמת ראיות קבועה (tier/code/reason/stability/spread_review/evidence_key היום כטקסט); hashes של קובצי הפלט ושל מודולי הייצוא (build_code_sha256 קיים); טווח תאריכים מפורש (היום "חודש סגור אחרון לכל תא").
